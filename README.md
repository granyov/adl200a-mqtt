# adl200a-mqtt

Небольшой надёжный **systemd-сервис** для Linux: опрашивает геотехнический
даталоггер **ACE Instrument ADL-200A** по RS-232 и публикует показания в локальный
**MQTT**-брокер в формате JSON.

Протокол ADL-200A недокументирован и проприетарен — он был реверс-инжинирен из
фирменной программы `ADL2Pro.exe` и подтверждён на живом железе. Полное описание —
в **[PROTOCOL.md](PROTOCOL.md)**.

## Что делает

- Держит постоянное соединение с портом (с автопереподключением).
- Раз в `ADL200A_INTERVAL` секунд шлёт `MEA` (измерение всех каналов, ~26 с).
- Разбирает покадровый ответ `MES` и публикует JSON в MQTT.
- Пишет лог в `stdout` (под systemd — в journald).

## Железо

Хост-порт логгера — **RS-232, 38400 8N1**. Две проверенные конфигурации:

| Хост | Адаптер | Устройство | Примечания |
|------|---------|-----------|------------|
| x86 ПК (напр. Dell Wyse) | Moxa UPort 1150 (USB↔RS-232) | `/dev/ttyUSB0` | нужна прошивка `moxa-1150.fw` (`firmware-misc-nonfree`) + драйвер `mxu11x0`; RS-232-режим сервис ставит сам |
| ARM SBC (напр. UVON) | нативный UART SoC через RS-232-трансивер | `/dev/ttyS0`, … | работает из коробки, драйверов не надо |

> RS-232 — точка-точка: логгер общается с одним хостом за раз.

## Установка

```sh
sudo ./install.sh
sudo nano /etc/default/adl200a        # указать ADL200A_PORT — свой порт
sudo systemctl enable --now adl200a
```

`install.sh` ставит зависимости (`python3-serial`, `python3-paho-mqtt`,
`mosquitto`), копирует файлы в `/opt/adl200a`, кладёт конфиг
`/etc/default/adl200a` и регистрирует сервис.

### Запуск на UVON (ARM, нативный RS-232)

Драйверов не нужно — UART SoC уже является RS-232-портом.

```sh
# 1. установка (зависимости + файлы + сервис)
sudo ./install.sh

# 2. указать порт, к которому подключён ADL-200A (ttyS0, ttyS1, …)
sudo sed -i 's#^ADL200A_PORT=.*#ADL200A_PORT=/dev/ttyS0#' /etc/default/adl200a

# 3. запустить и включить автозапуск
sudo systemctl enable --now adl200a

# 4. смотреть лог
journalctl -u adl200a -f
```

Проверить, что логгер отвечает (сервис держит порт монопольно — сначала остановить):

```sh
sudo systemctl stop adl200a
ADL200A_PORT=/dev/ttyS0 python3 /opt/adl200a/ace.py GTT     # должен вернуть время
sudo systemctl start adl200a
```

> Если `ttyS*` на плате — это **TTL-UART 3.3 В** (гребёнка), а не полноценный RS-232
> (±12 В на трансивере), напрямую к логгеру подключать нельзя — нужен модуль
> **MAX3232** между UART и RS-232 логгера.

## Конфигурация — `/etc/default/adl200a`

| Переменная | По умолчанию | Значение |
|-----------|--------------|----------|
| `ADL200A_PORT` | `/dev/ttyUSB0` | последовательный порт логгера |
| `ADL200A_BAUD` | `38400` | скорость |
| `ADL200A_ID` | `1` | Logger ID |
| `ADL200A_INTERVAL` | `60` | секунд между циклами измерения |
| `ADL200A_MQTT_HOST` / `_PORT` | `127.0.0.1` / `1883` | MQTT-брокер |
| `ADL200A_TOPIC` | `adl200a` | префикс MQTT-топиков |
| `ADL200A_SENSORS` | `/etc/adl200a/sensors.json` | калибровки датчиков (см. ниже) |

После правки конфига: `sudo systemctl restart adl200a`.

## Как забрать данные из сервиса

Демон публикует в локальный MQTT-брокер (mosquitto). Забрать может что угодно,
что умеет MQTT: дашборд, Node-RED, Home Assistant, Telegraf/InfluxDB или свой
скрипт.

### Какие каналы приходят

Каждый цикл шлёт `MEA`. Логгер опрашивает **только те каналы, что включены в его
собственной конфигурации**, — посмотреть её можно командой `GCC`:

```
<<!01,01,GCC:02,1,1,1,0020,6;   <- канал включён
<<!01,01,GCC:03,0,0,0,0000,0;   <- канал выключен, в MEA его не будет
```

Ответ на `MEA` приходит **канал за каналом с паузами в несколько секунд**, поэтому
«давно нет данных» — плохой признак конца развёртки: он режет её пополам, и остаток
всплывает в следующем цикле (в журнале это видно как `Published 1 channels` через
раз). Сервис спрашивает `GCC` при старте и ждёт ровно включённые каналы:

```
Logger sweeps channels 02, 04
Published 2 channels (196 raw bytes)
```

### Изменить набор каналов — `channels.py`

Какие каналы опрашивать, решает сам прибор. Посмотреть и поменять:

```sh
python3 /opt/adl200a/channels.py --show                # только посмотреть
python3 /opt/adl200a/channels.py --enable-all          # сухой прогон
python3 /opt/adl200a/channels.py --enable-all --yes    # включить все 16
python3 /opt/adl200a/channels.py --only 1 --yes        # оставить только канал 01
```

Порт занят службой — инструмент останавливает её сам и возвращает на выходе,
в том числе при ошибке (`--no-service`, чтобы не трогал).

Без `--yes` в прибор ничего не пишется. Копия конфигурации снимается **только
перед настоящей записью**, так что до первой записи возвращать нечего. После
записи вернуть всё как было:

```sh
python3 /opt/adl200a/channels.py --restore /var/lib/adl200a/gcc-backup.txt --yes
```

Формат команды взят из вендорского `ADL2Pro.exe`, не угадан:
`>>?1,%d,SCC:%d,%d,%d,%d,%d,%d;` — канал, использовать, тип (1=VW, 2=аналог),
температура, и два числовых параметра. У включённого канала на этом приборе:
`1,1,1,20,6`.

**Цена вопроса высокая.** Развёртка идёт по включённым каналам последовательно:
два канала — около 6 с, четырнадцать — около 23 с. Но дело не только в скорости:
на полном наборе каналов прибор оказывается занят почти всё время и начинает
**тормозить со служебными командами** — `GCC` и `GTT` отвечают с задержкой в
20-30 секунд или не отвечают вовсе, ответы приезжают уже к следующей команде, а
циклы `MEA` идут рвано (то все каналы, то один). Поэтому:

- включить все каналы удобно **один раз**, чтобы найти, к какому подключён датчик;
- сразу после этого оставить только рабочие: `--only 1 --yes`.

Инструмент к этому готов: перед чтением и записью он ждёт, пока прибор замолчит,
принимает конфигурацию только целиком (все 16 строк) и различает «не применилось»
и «не смог проверить».

Сервис публикует ровно то, что пришло:

- `adl200a/ch/NN` — по каналу (JSON);
- `adl200a/measurement` — весь цикл одним JSON;
- `adl200a/ch/NN/pressure`, `/temperature`, `/frequency`, `/digits` — те же величины
  голым числом, если для канала есть калибровка (удобно для Telegraf и дашбордов).

У каждого канала два сырых значения: `t01` — струнный датчик и `t06` —
сопротивление термистора в омах (3 кОм ≈ 25 °C). Оборванный канал видно сразу:
`t01 = 0`, а `t06` уходит далеко за 110 кОм.

## Калибровка — `/etc/adl200a/sensors.json`

Сертификат от ACE Instrument даёт всё, что нужно для перевода сырых отсчётов в
инженерные единицы. Переносим его в JSON, по одной записи на канал
(шаблон — [`sensors.example.json`](sensors.example.json)):

```json
{"channels": {"02": {
  "name": "VW earth pressure cell", "model": "1910", "serial": "587968",
  "unit": "kgf/cm2", "range": 3.5, "cal_temp_c": 24.0, "initial_temp_c": null,
  "raw_unit": "auto", "hz_min": 2280.4, "hz_max": 2991.4,
  "polynomial": {"A": -0.00000088515, "B": -0.000254190, "C": 8.68208},
  "linear": {"gage_factor": -0.00093328, "zero_reading": 8946.19},
  "thermal_coefficient": -0.00037901, "thermistor": "3k"}}}
```

Считается ровно по формулам сертификата:

- давление (основное) — `P = A·Hz² + B·Hz + C − Tct·(Tc − Ti)`;
- давление (линейная проверка) — `P = G·(digits − zero) − Tct·(Tc − Ti)`, `digits = Hz²/1000`;
- температура — Стейнхарт–Харт по термистору 3 кОм @ 25 °C:
  `1/T = 1.4051·10⁻³ + 2.369·10⁻⁴·lnR + 1.019·10⁻⁷·(lnR)³`.

`initial_temp_c` — температура на момент установки, от неё считается температурная
поправка; `null` означает «брать температуру калибровки».

### `raw_unit` — в каких единицах логгер отдаёт `t01`

Масштаб поля `t01` зависит от режима измерения логгера, поэтому он задаётся явно:
`hz`, `hz_x100`, `digits`, `digits_x10`. При `"auto"` сервис подбирает его по
паспортному окну `hz_min`…`hz_max` на первом же реальном отсчёте, запоминает и
пишет в журнал:

```
ch 02: TYPE 01 reads as digits_x10 -> 2867.63 Hz
```

Варианты различаются больше чем в 10 раз, так что подходит всегда ровно один.
Посмотреть все разом:

```sh
python3 /opt/adl200a/calibration.py --explain 82233
python3 /opt/adl200a/calibration.py --channel 02 --raw 82233 --therm 2987
```

### Живая сессия в консоли — `live.sh`

Для настройки и установки датчиков: таблица в реальном времени, сырые отсчёты
рядом с инженерными величинами, в конце — сводка с размахом и дрейфом.

```sh
/opt/adl200a/live.sh                 # из MQTT, службу не трогает (раз в минуту)
/opt/adl200a/live.sh -d              # прямой опрос: цикл ~10 с вместо минуты
/opt/adl200a/live.sh -d -z -c 02     # только канал 02, Δ от первого отсчёта
/opt/adl200a/live.sh -d -r -l /tmp/установка.log   # + кадры протокола, с записью в файл
```

```
   время  ch        t01       t06        Гц     digits     кгс/см²       кПа     %FSR       °C  статус
--------  --  ---------  --------  --------  ---------  ----------  --------  -------  -------  ------
16:38:50  02      89485      3007   2991.40     8948.5      0.0013      0.13    0.04%    24.94  ok
16:38:50  04          0    240279         —          —           —         —        —        —  обрыв
```

В режиме `-d` служба на время сессии останавливается и возвращается на выходе
(Ctrl-C или `-n N` строк) — иначе порт занят демоном. Полный список ключей:
`live.sh -h`.

Через ssh запускай с `-t`, иначе Ctrl-C оборвёт только ssh-клиент: сессия на плате
завершится сама (по обрыву трубы) и службу вернёт, но сводку на экране ты не
увидишь — её сохранит `-l ФАЙЛ`.

```sh
ssh -t astra '/opt/adl200a/live.sh -d -z -c 02'
```

### Из консоли

```sh
mosquitto_sub -h 127.0.0.1 -t 'adl200a/#' -v          # всё
mosquitto_sub -h 127.0.0.1 -t 'adl200a/ch/02' -v      # один канал
mosquitto_sub -h 127.0.0.1 -t 'adl200a/ch/02/pressure'  # только давление, числом
mosquitto_sub -h 127.0.0.1 -t 'adl200a/measurement' -v  # весь цикл
```

### Из кода (Python)

Готовый пример — [`examples/subscribe.py`](examples/subscribe.py):

```sh
python3 examples/subscribe.py                 # локально
python3 examples/subscribe.py 100.71.138.46   # с другого хоста (см. ниже)
```

### С другой машины

По умолчанию mosquitto слушает только `localhost`. Чтобы читать данные удалённо:
- запусти консьюмер на самом хосте логгера, **или**
- пробрось порт: `ssh -L 1883:127.0.0.1:1883 uvon-debian`, затем подключайся к
  `127.0.0.1:1883` у себя, **или**
- настрой в mosquitto внешний listener / bridge.

### Формат сообщения (топик `adl200a/ch/NN`)

```json
{"channel": 2, "values": {"t01": 82233, "t06": 2987},
 "dev_date": "26/09/30", "dev_time": "16:09:42",
 "timestamp": "2026-09-30T13:09:42+00:00",
 "eng": {"sensor": "VW earth pressure cell", "status": "ok",
         "model": "1910", "serial": "587968",
         "temperature_c": 25.09, "thermistor_ohms": 2987,
         "raw_unit": "digits_x10", "frequency_hz": 2867.63, "digits": 8223.3,
         "pressure": 0.6747, "pressure_unit": "kgf/cm2", "pressure_kpa": 66.167,
         "pressure_linear": 0.6751, "percent_fsr": 19.28}}
```

`values` — всегда сырые отсчёты. Блок `eng` появляется, когда для канала есть
запись в `sensors.json`; поле `status` говорит, можно ли верить числам:

| `status` | Что значит |
|----------|-----------|
| `ok` | всё посчитано |
| `no_temperature` | струна читается, термистор оборван — температурной поправки нет |
| `no_vw_signal` | `t01 = 0`, струна не отвечает |
| `disconnected` | нет ни струны, ни термистора — канал пустой |
| `unresolved_scale` | `t01` не лёг ни в один масштаб из `hz_min`…`hz_max` |

## Файлы

- `adl200a_mqtt.py` — демон;
- `calibration.py` — перевод сырых отсчётов в инженерные единицы (+ CLI);
- `live.sh` — живая консольная сессия для настройки и установки;
- `channels.py` — посмотреть и изменить набор опрашиваемых каналов в приборе;
- `sensors.example.json` — шаблон калибровок по каналам;
- `ace.py` — CLI для одной ACE-команды (`ace.py GTT`, `ace.py MEA`, …);
- `sniffer.py` — низкоуровневый hex-пробник порта;
- `prestart.sh` — ставит RS-232-режим на Moxa UPort 1150 (на прочих портах — ничего);
- `adl200a.service` / `adl200a.default` — systemd-юнит + шаблон конфига;
- `install.sh` — установщик;
- `examples/subscribe.py` — пример MQTT-консьюмера.
