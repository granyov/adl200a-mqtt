# Подключение датчика давления ACE Instruments 1910 к логгеру ADL-200A

Инструкция для установщиков: от распаковки датчика до проверенных показаний в MQTT.
Подходит и для модели **1911** — это та же ячейка меньшего диаметра (Ø150 мм
вместо Ø230 мм) с тем же струнным датчиком и термистором.

В конце — как самим настроить масштабы для датчиков с другими выходами:
mV, Bridge, Resistance, RTD и Serial.

Команды выполняются на плате, к которой подключён логгер (`ssh -t <пользователь>@<плата>`).
Всё ПО лежит в `/opt/adl200a`, настройки — в `/etc/adl200a/sensors.json`.

Всё нужное — на GitHub: **https://github.com/granyov/adl200a-mqtt**. Эта инструкция с
помощниками (паспорт → настройки, подбор множителя, журнал) — страницей:
**https://granyov.github.io/adl200a-mqtt/**. ПО — в разделе
[Releases](https://github.com/granyov/adl200a-mqtt/releases/latest).

---

## 1. Что понадобится

- Ячейка давления 1910 (или 1911) с кабелем.
- **Паспорт калибровки (Calibration Sheet) именно этой ячейки** — по серийному
  номеру. У каждой ячейки свои коэффициенты; чужие брать нельзя.
- Логгер ACE ADL-200A и кабель RS-232 до платы.
- Плата с `adl200a-mqtt` версии **1.1.0 или новее** — установка в разделе 1а.
- Журнал установки (шаблон в разделе 10).

### Коротко о датчике

| Параметр | Значение |
|----------|----------|
| Принцип | струнный (VW): давление меняет частоту струны |
| Диапазоны модели | 2–70 кгс/см² (точный — в паспорте) |
| Разрешение / точность | 0,025 % / ±0,1 % от верхнего предела (FSR) |
| Перегрузка | до 150 % FSR |
| Температура работы | −40…+80 °C |
| Встроенный термистор | 3 кОм при 25 °C, ±0,5 °C, −40…+105 °C |
| Кабель | 4 жилы 0,37 мм², в экране, оболочка PU |

Частота струны **падает** с ростом давления: у ячейки s/n 587968 это 2991 Гц
без нагрузки и 2280 Гц на пределе 3,5 кгс/см².

## 1а. Установка ПО с GitHub

Файлы — на странице релиза: https://github.com/granyov/adl200a-mqtt/releases/latest

**UVON на Astra 4.7.11 arm64, без интернета** — полный комплект: программа, Python,
Mosquitto и все зависимости одним архивом. Скачай `adl200a-mqtt-<версия>-offline-astra-4.7.11-arm64.tar.gz`
и перенеси на плату:

```sh
scp adl200a-mqtt-1.1.0-offline-astra-4.7.11-arm64.tar.gz <пользователь>@<плата>:
```

На плате:

```sh
tar -xzf adl200a-mqtt-1.1.0-offline-astra-4.7.11-arm64.tar.gz
cd adl200a-offline-astra-4.7.11-arm64
sudo sh install-offline.sh
sudo adl200a-configure /dev/ttyS5 38400
```

Установщик сверяет контрольные суммы, архитектуру и версию ОС и не ходит в интернет.
Комплект — только для Astra 4.7.11 arm64. В `adl200a-configure` укажи порт, к
которому подключён логгер (`/dev/ttyS4` или `/dev/ttyS5` на UVON, `/dev/ttyUSB0` для Moxa).

**Другая плата с Debian или Astra**, где уже есть Python 3.7+, systemd и Mosquitto, —
только пакет программы:

```sh
sudo dpkg -i adl200a-mqtt_1.1.0_all.deb
sudo adl200a-configure /dev/ttyS5 38400
```

Обновление ставится так же, поверх: настройки `/etc/default/adl200a` и
`/etc/adl200a/sensors.json` сохраняются. Проверить версию:

```sh
dpkg -s adl200a-mqtt | grep Version
```

Пример настроек и эта инструкция после установки лежат в
`/usr/share/doc/adl200a-mqtt/`.

## 2. Проверка на столе до монтажа

Сделай это до того, как ячейка уйдёт в грунт: после засыпки ошибку подключения
или неисправный датчик уже не исправить.

1. Подключи ячейку к свободному каналу логгера (раздел 3) и пропиши её в
   `sensors.json` (раздел 4).
2. Настрой канал (раздел 5) и запусти живую сессию (раздел 6).
3. Ненагруженная ячейка должна показать:
   - статус `ok`;
   - частоту рядом с частотой нулевого давления из паспорта (у s/n 587968 —
     около 2991 Гц);
   - давление около нуля — с поправкой на разницу температур, обычно в пределах
     нескольких тысячных кгс/см²;
   - температуру помещения.

Если что-то не так — раздел 8.

## 3. Подключение кабеля к логгеру

Цвета жил — в паспорте, в блоке **Cable Connection**. Для 1910 это:

| Пара | Жилы | Куда |
|------|------|------|
| **Frequency** (струна) | красная, чёрная | струнный вход (VW) выбранного канала |
| **Temperature** (термистор) | зелёная, белая | вход термистора того же канала |
| Экран | — | на клемму экрана/земли канала, если она есть |

Клеммы — по маркировке клеммника ADL-200A.

- **Полярность значения не имеет**: катушка струны и термистор — не полярные
  элементы. Важно только не перепутать пары между собой.
- **Длина кабеля на струну не влияет** — частота не зависит от сопротивления
  линии. На термистор влияет, но мало: 25 м кабеля 0,37 мм² занижают температуру
  примерно на 0,02 °C, 300 м — примерно на 0,2 °C.
- **Запиши номер канала** (1–16) в журнал и промаркируй кабель у клеммника.

Логгер подключается к плате по RS-232, 38 400 бод, 8N1. Порт задаёт
`adl200a-configure` (раздел 1а), он записывается в `/etc/default/adl200a`
(`ADL200A_PORT`). Проверить, что логгер отвечает:

```sh
sudo systemctl stop adl200a
ADL200A_PORT=/dev/ttyS5 python3 /opt/adl200a/ace.py GTT
sudo systemctl start adl200a
```

Подставь свой порт. В ответ должно прийти время логгера: `<<!01,01,GTT:10:27:16;`.

## 4. Паспорт → `sensors.json`

Открой файл:

```sh
sudo nano /etc/adl200a/sensors.json
```

Добавь запись канала. Ключ — номер канала двумя цифрами. Пример для ячейки
s/n 587968 на канале 01:

```json
{
  "channels": {
    "01": {
      "name": "Ячейка давления, ПК 12+40, отметка −3,5",
      "model": "1910",
      "serial": "587968",
      "unit": "kgf/cm2",
      "range": 3.5,
      "sweep": "auto",
      "analog": "thermistor_3k",
      "cal_date": "2025-11-25",
      "cal_temp_c": 24.0,
      "initial_temp_c": null,
      "raw_unit": "hz_x100",
      "hz_min": 2280.4,
      "hz_max": 2991.4,
      "polynomial": {"A": -8.8515e-07, "B": -0.00025419, "C": 8.68208},
      "linear": {"gage_factor": -0.00093328, "zero_reading": 8946.19},
      "thermal_coefficient": -0.00037901,
      "thermistor": "3k"
    }
  }
}
```

Откуда что брать:

| Поле | Из паспорта | Пример |
|------|-------------|--------|
| `name` | своё: где стоит ячейка | `"Ячейка давления, ПК 12+40"` |
| `model` | Model | `"1910"` |
| `serial` | Serial No. | `"587968"` |
| `range` | Range, в кгс/см² | `3.5` |
| `cal_date` | Cal. Date | `"2025-11-25"` |
| `cal_temp_c` | Cal. Temp | `24.0` |
| `hz_max` | столбец **Hz** в строке **0.0** (нулевое давление) | `2991.4` |
| `hz_min` | столбец **Hz** в последней строке (максимальное давление) | `2280.4` |
| `polynomial.A`, `B`, `C` | Polynomial Factor: A, B, C Factor — **со знаками** | `-8.8515e-07` |
| `linear.gage_factor` | Linear Factor: Gage Factor — со знаком | `-0.00093328` |
| `linear.zero_reading` | Linear Factor: Zero Reading | `8946.19` |
| `thermal_coefficient` | Thermal Coefficient — со знаком | `-0.00037901` |

Остальное — как в примере:

- `"sweep": "auto"` — полосу развёртки программа выберет сама по `hz_min`…`hz_max`.
- `"analog": "thermistor_3k"` — на этом же канале термистор.
- `"raw_unit": "hz_x100"` — так логгер передаёт частоту (подтверждено на приборе).
- `"unit": "kgf/cm2"` — паспорт ACE даёт коэффициенты в кгс/см²; кПа программа
  посчитает сама.
- `"initial_temp_c": null` — пока ячейка не установлена (раздел 7).

Частые ошибки:

- **Потерян минус** у A, B, gage factor или thermal coefficient — давление выйдет
  огромным или отрицательным.
- `8.8515e-07` — это 0,00000088515. Пиши так же, как в паспорте, просто с точкой.
- **Перепутаны** `hz_min` и `hz_max` — программа это переживёт, но для порядка:
  `hz_max` — частота при нулевом давлении.
- **Запятая вместо точки** в числах — файл не прочитается.

Проверь файл:

```sh
python3 /opt/adl200a/calibration.py --check
```

Должно быть `/etc/adl200a/sensors.json в порядке`. Иначе программа перечислит
все ошибки сразу.

Сверка с паспортом: подставь частоту из любой строки таблицы паспорта —
давление должно совпасть со столбцом **Calculated Pressure** до тысячных. Для
s/n 587968 строка 1.4 кгс/см² — это 2728,3 Гц:

```sh
python3 /opt/adl200a/calibration.py --channel 1 --raw 272830
```

`--raw` — частота × 100. В ответе `"pressure": 1.3999` при паспортных 1.400.
Статус будет `no_temperature`: без `--therm` температурная поправка не
считается — для сверки с паспортом так и нужно.

## 5. Настройка канала логгера

У каждого канала логгера два входа: **струнный** с полосой развёртки и
**аналоговый** с типом датчика. С завода стоит полоса **Sweep 01 (450–1200 Гц)**
— она **не накрывает** ячейку 1910 (2280–2991 Гц), и датчик на ней не читается
или читается со скачками. Нужна **Sweep 03 (1400–3500 Гц)** — её и выберет
`"sweep": "auto"`.

Сначала сухой прогон — в логгер ничего не пишется:

```sh
python3 /opt/adl200a/channels.py --apply
```

Посмотри, что поменяется:

```
≠ 01   VW Sweep 01 (450–1200 Гц) + Thermistor 3K       VW Sweep 03 (1400–3500 Гц) + Thermistor 3K  [полоса выбрана по сертификату]
≠ 02   VW Sweep 01 (450–1200 Гц) + Thermistor 3K       выключен (нет в файле)
...
  после: включено каналов 1, развёртка ≈ 5 с
  (сухой прогон) >>?1,1,SCC:1,1,1,3,20,6;
```

- Для ячейки 1910 на канале N должна уйти команда `SCC:N,1,1,3,20,6`.
- **Каналы, которых нет в файле, выключаются.** Так и задумано: каждый лишний
  канал удлиняет опрос примерно на 5 секунд, а при 10–15 включённых каналах
  логгер начинает тормозить. Если на других каналах есть датчики, которые ещё не
  внесены в файл, — сначала внеси их или добавь ключ `--keep-others`.

Если всё верно — запиши:

```sh
python3 /opt/adl200a/channels.py --apply --yes
```

Программа сама остановит службу, снимет копию старой настройки, запишет,
перечитает, сверит и вернёт службу. В конце должно быть `всё применилось`.
Куда легла копия, программа печатает (обычно `/var/lib/adl200a/gcc-backup.txt`;
если у твоего пользователя туда нет доступа — в домашний каталог). Вернуть как было:

```sh
python3 /opt/adl200a/channels.py --restore /var/lib/adl200a/gcc-backup.txt --yes
```

Посмотреть настройку логгера в любой момент:

```sh
python3 /opt/adl200a/channels.py --show
```

## 6. Проверка показаний

Живая сессия с прямым опросом логгера — новый отсчёт каждые несколько секунд:

```sh
ssh -t <пользователь>@<плата> '/opt/adl200a/live.sh -d -z -c 1'
```

- `-d` — прямой опрос (служба на время сессии встаёт на паузу и потом возвращается);
- `-z` — столбец Δ: изменение от первого отсчёта сессии;
- `-c 1` — только канал 1;
- `ssh -t` — обязательно, иначе Ctrl-C не дойдёт до сессии и сводки не будет;
- `-l /tmp/канал01.log` — дополнительно записать сессию в файл.

```
по файлу ch01: VW Sweep 03 (1400–3500 Гц) + Thermistor 3K  [полоса выбрана по сертификату]
в приборе ch01: VW Sweep 03 (1400–3500 Гц) + Thermistor 3K

   время  ch     VW t01  терм t06        Гц     digits     кгс/см²          Δ       кПа     %FSR       °C  статус
--------  --  ---------  --------  --------  ---------  ----------  ---------  --------  -------  -------  ------
10:27:59  01     294720      3344   2947.20     8686.0      0.2440    +0.0000     23.93    6.97%    22.53  ok
```

Как читать:

- **Статус `ok`** — струна и термистор отвечают.
- **Гц** внутри диапазона паспорта (с небольшим запасом при перегрузке).
- **Стабильность**: за 10–20 отсчётов на неподвижной ячейке размах давления
  обычно в тысячных кгс/см² (разрешение датчика — 0,025 % FSR). Скачки на
  десятые — неверная полоса или плохой контакт.
- **°C** — правдоподобная температура среды.
- **Нет строки «НЕ КАК В ФАЙЛЕ»** — если она есть, логгер настроен не так, как
  описано в файле: повтори раздел 5.

Ctrl-C завершает сессию и печатает сводку: число отсчётов, минимум, максимум,
размах и дрейф.

## 7. Монтаж и нулевой отсчёт

Монтаж — по проекту и руководству ACE. Из рекомендаций производителя:

- ячейка ставится всей рабочей поверхностью в контакт с грунтом;
- для точного измерения зазоры между ячейкой, опорной плитой и металлоконструкциями
  заполняют эпоксидной смолой;
- в насыпях ячейки обычно ставят группами по 3–5 в разных ориентациях
  (вертикально, горизонтально, под 45°) — как в проекте.

Во время засыпки держи открытой живую сессию с `-z`: столбец Δ показывает, как
растёт давление, а сразу видно, не пропал ли сигнал.

**Нулевой отсчёт.** После монтажа, до нагрузки, когда показания установились
(температура перестала меняться — обычно через час-два), сними 10–20 отсчётов и
запиши в журнал среднее: частоту, digits, давление и температуру.

Температуру этого момента впиши в `sensors.json`:

```json
"initial_temp_c": 12.4
```

От неё считается температурная поправка `−Tct·(Tc − Ti)`. Пока там `null`,
поправка считается от температуры калибровки. Для 1910 ошибка небольшая —
0,0004 кгс/см² на градус, — но для длительных наблюдений её лучше убрать.
Перезапускать ничего не нужно: консольные инструменты читают файл при каждом
запуске.

## 8. Если что-то не так

| Что видно | Вероятная причина | Что делать |
|-----------|-------------------|------------|
| `обрыв`: `VW t01 = 0`, `терм t06` > 110 000 | канал пустой: кабель не подключён, не тот канал, обрыв кабеля | проверить канал и клеммы, прозвонить кабель |
| `нет струны`: `VW t01 = 0`, температура есть | неверная полоса; пары перепутаны; обрыв струнной пары | `channels.py --show` — должна быть Sweep 03; проверить красную и чёрную жилы |
| `нет темп.`: частота есть, температуры нет | обрыв или ошибка в термисторной паре | проверить зелёную и белую жилы |
| строка `НЕ КАК В ФАЙЛЕ` | логгер настроен не по файлу | `channels.py --apply`, потом `--yes` |
| `… Гц вне полосы прибора` | полоса не накрывает датчик | `"sweep": "auto"` и `--apply` |
| давление скачет на десятые | неверная полоса или плохой контакт | проверить полосу и клеммы |
| давление огромное или отрицательное без нагрузки | потерян знак коэффициента; чужой паспорт | сверить `sensors.json` с паспортом **этой** ячейки |
| `масштаб?` | не тот `raw_unit` | должно быть `"hz_x100"` |
| `--apply` пишет «есть ошибки, прибор не трогаю» | ошибка в файле | исправить всё, что перечислено |
| `не удалось прочитать конфигурацию целиком` | логгер занят опросом | повторить через минуту; выключить лишние каналы |
| `логгер не ответил` | кабель RS-232, порт, питание логгера | `ace.py GTT` (раздел 3) |

## 9. Что уходит в MQTT

Служба публикует **сырые** значения логгера — пересчёт в давление в MQTT не
подмешивается, чтобы ряд в базе не зависел от файла с коэффициентами:

```json
adl200a/ch/01  {"channel": 1, "values": {"t01": 294720, "t06": 3344},
                "dev_date": "26/11/03", "dev_time": "10:27:59", "timestamp": "…"}
```

- `t01` — частота струны × 100: `294720` → 2947,20 Гц;
- `t06` — сопротивление термистора, Ом.

Что значит каждое значение на каждом канале, публикуется в retained-топике
`adl200a/config` — его читает тот, кто строит графики. Давление из сырых значений
считается по тем же формулам паспорта:

```
Hz = t01 / 100
P  = A·Hz² + B·Hz + C − Tct·(T − Ti)          [кгс/см²; × 98,0665 → кПа]
```

где T — температура по термистору (кривая Стейнхарта–Харта для 3 кОм),
Ti — `initial_temp_c`.

## 11. Другие датчики: mV, Bridge, Resistance, RTD, Serial

Кроме струнного входа и термистора у канала ADL-200A есть аналоговые входы:
**mV**, **Bridge** (мост), **Resistance** (сопротивление), **RTD** (платиновый
термометр) и **Serial** (цифровой датчик). В каком виде логгер передаёт их
значения, на живом приборе ещё не проверялось, поэтому масштаб задаёт установщик
— в блоке `analog_scale` канала.

### 11.1. Как устроен пересчёт

```
сырое целое из логгера  × raw_multiplier  →  величина на входе (мВ, Ом, мВ/В …)
величина на входе  →  linear | polynomial | function  →  результат (кПа, мм, °C …)
```

```json
"05": {
  "name": "Датчик давления с выходом мВ",
  "sweep": null,
  "analog": "mv",
  "analog_scale": {
    "raw_multiplier": 0.001,
    "input_unit": "мВ",
    "linear": {"gage_factor": 2.0, "zero_reading": 0.5},
    "unit": "кПа",
    "quantity": "давление"
  }
}
```

| Поле | Что это |
|------|---------|
| `sweep` | `null` — струнного входа у такого датчика нет |
| `analog` | `mv`, `bridge`, `resistance`, `rtd` или `serial` |
| `raw_multiplier` | во сколько раз умножить сырое целое, чтобы получить величину на входе; находится по эталону (11.2) |
| `input_unit` | единица на входе — для подписи |
| `linear` | результат = `gage_factor` · (вход − `zero_reading`) |
| `polynomial` | результат = c0 + c1·x + c2·x² + …, задаётся списком `[c0, c1, c2]` |
| `function` | готовая кривая: `pt100` или `pt1000` (RTD → °C по IEC 60751) |
| `unit`, `quantity` | единица и название результата — для подписи |

Задаётся **что-то одно** из `linear`, `polynomial`, `function` — или ничего: тогда
показывается только величина на входе. Именно так и удобно подбирать
`raw_multiplier`.

`bridge` и `serial` нельзя ставить на канал вместе со струнным входом — так решил
производитель логгера. У `serial` обязательно `"serial_count"` — сколько значений
отдаёт датчик.

### 11.2. Как найти `raw_multiplier`

Нужен эталон с известным значением: калибратор напряжения для mV, точный
резистор или магазин сопротивлений для Resistance и RTD, имитатор моста для
Bridge.

1. Пропиши канал **без** пересчёта — только `raw_multiplier: 1`:
   ```json
   "analog_scale": {"raw_multiplier": 1, "input_unit": "мВ"}
   ```
2. Включи канал: `channels.py --apply`, затем `--yes`.
3. Подай эталон на вход и посмотри сырое число в живой сессии:
   ```sh
   ssh -t <пользователь>@<плата> '/opt/adl200a/live.sh -d -c 5'
   ```
   В конце строки: `ok  (mV(t02) 12345 мВ (пересчёт не задан))`.
4. `raw_multiplier = эталон / сырое число`. Подал 12,345 мВ, увидел 12345 —
   множитель `0.001`.
5. **Проверь на второй точке**, лучше у другого края диапазона: при правильном
   множителе вход совпадёт с эталоном. Если нет, масштаб нелинейный или у входа
   есть смещение — запиши обе точки и сообщи разработчикам.
6. Впиши найденный множитель и пересчёт из паспорта датчика.

### 11.3. Примеры

Числа в примерах условные: коэффициенты бери из паспорта своего датчика,
`raw_multiplier` — из подбора по эталону.

**mV** — датчик с милливольтовым выходом и линейной характеристикой
«чувствительность и ноль»:

```json
"analog": "mv",
"analog_scale": {"raw_multiplier": 0.001, "input_unit": "мВ",
                 "linear": {"gage_factor": 2.0, "zero_reading": 0.5},
                 "unit": "кПа", "quantity": "давление"}
```

**Bridge** — тензомост, паспорт даёт полином по мВ/В:

```json
"analog": "bridge",
"analog_scale": {"raw_multiplier": 0.0001, "input_unit": "мВ/В",
                 "polynomial": [0.0, 125.0],
                 "unit": "мкм/м", "quantity": "деформация"}
```

**Resistance** — потенциометрический датчик перемещения, 0–1000 Ом на 0–100 мм:

```json
"analog": "resistance",
"analog_scale": {"raw_multiplier": 0.1, "input_unit": "Ом",
                 "polynomial": [0.0, 0.1], "unit": "мм", "quantity": "перемещение"}
```

**RTD** — PT100, достаточно найти множитель до омов, кривая встроена:

```json
"analog": "rtd",
"analog_scale": {"raw_multiplier": 0.01, "input_unit": "Ом", "function": "pt100"}
```

Проверка множителя для RTD: эталонный резистор 100,00 Ом должен дать 0,00 °C,
138,51 Ом — 100,00 °C.

**Serial** — цифровой датчик с несколькими значениями:

```json
"sweep": null,
"analog": "serial",
"serial_count": 3,
"analog_scale": {"raw_multiplier": 1}
```

Для Serial **формат кадров на приборе не проверен**: какие значения и в каком
виде приходят, неизвестно, а пересчёт применяется к значению `t04`. Перед вводом
такого датчика в работу сними сессию с кадрами протокола и передай её
разработчикам:

```sh
ssh -t <пользователь>@<плата> '/opt/adl200a/live.sh -d -r -c 6 -l /tmp/serial.log'
```

### 11.4. Проверка

```sh
python3 /opt/adl200a/calibration.py --check                  # весь файл
python3 /opt/adl200a/calibration.py --channel 5 --analog 12345   # одно значение
ssh -t <пользователь>@<плата> '/opt/adl200a/live.sh -d -z -c 5'
```

В живой сессии результат — в конце строки, а в сводке — отдельной строкой
«аналог»:

```
10:50:37  05          —         —         —          —           —          —         —        —        —  ok  (mV(t02) 12.345 мВ → 23.6900 кПа (Δ +0.0000))
…
сводка за сессию
  ch05 аналог отсчётов 20   мин 23.6900   макс 23.6912   среднее 23.6905   размах 0.0012   дрейф от первого +0.0005 кПа
```

В MQTT, как и для струнных датчиков, уходит только сырое целое: для mV это
`t02`, Bridge — `t03`, Serial — `t04`, Resistance — `t05`, RTD — `t07`.
